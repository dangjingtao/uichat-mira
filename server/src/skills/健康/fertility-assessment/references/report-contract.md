# 备孕全景评估 — Report Contract

本 reference 定义 `fertility-assessment` 的最终报告阶段。

报告是同一个 Skill 的交付物，不是第二个可发现 Skill。

## 1. 唯一事实源

报告必须基于已经形成的结构化 assessment state。

禁止在报告阶段重新从聊天历史临时拼装一套新的事实源。

```text
assessment state
→ 报告模型按已发布规则归类证据（不打分）
→ 确定性评分引擎计算分数 / 置信度 / 完整度
→ 内容治理：去重、医学措辞收边、无资料维度压缩
→ Report ViewModel
→ deterministic inline HTML + static SVG charts
→ 同一 HTML 交给 Vivliostyle 生成 PDF
```

同一份结构化状态是内容真相；同一份 Report ViewModel 是评分真相；同一份 HTML 是最终视觉真相。

## 2. 报告至少包含

1. 专属服务封面、服务对象、评估类型与团队信息；
2. 自动目录和 PDF 章节页码；
3. 评分规则版本与阅读说明；
4. 当前优势、优先事项、就诊准备与生活方式重点；
5. 所选评估对象对应的十维雷达图；
6. 所选评估对象对应的十维评分条与置信度；
7. 女性十维详细画像（仅 female / couple）；
8. 男性十维详细画像（仅 male / couple）；
9. 资料缺口与不确定项；
10. “写在最后”祝福总结；
11. 医疗免责声明；
12. 页眉页脚、页码与 PDF 分页保护。

## 3. 维度字段一致性

男女双方每个最终维度保持一致字段：

```text
id
score: number (0~10)
confidence: low | medium | high
dataCompleteness: 0~1
evidence
strengths
concerns
missingEvidence
interpretation
actions.selfCare
actions.discussWithClinician
actions.testsToConsider
```

规则：

- 最终报告中的每个已选择维度必须有数值分，不允许空白维度或 `score = null`；
- 无直接证据时使用 `5.0 / low` 中性参考基准，并显示“参考基准 · 暂不可充分评价”；
- 资料越少，极端结果越应向中性基准收缩；
- `score` 不是怀孕概率、临床妊娠率或活产率；
- evidence 必须来自结构化状态中的已知事实；
- 用户口述而未核验的结果必须保留 `user_reported` 语义；
- 需要医疗决策的内容进入就诊讨论问题；
- 不输出处方药方案或个体化药物 / 补充剂剂量。

## 4. 用户可见栏目责任

为避免一份事实在多个栏目机械重复：

- **已有依据**：只放用户已提供、可追溯的事实；
- **当前关注**：只放由已有事实推导出的影响或需要核对的方向，不复述原事实；
- **建议补充**：只放当前确实缺失、且补充后可能改变判断的信息；
- **现阶段可做的准备**：只放非医疗决策性质、与现有证据相关的整理或生活准备；
- **就诊时可问**：把促排、移植、药物、补充剂、手术和专业检查写成问题，不替用户决定；
- **可与医生确认的检查**：说明“是否有必要、何时做更合适”，不写成人人必查。

内容治理层应对同栏和跨栏进行通用语义去重，不依赖某个具体病例的固定句子。

## 5. 评分责任边界

评分规则由 `references/scoring-rules.yaml` 发布并版本化；用户可读说明见 `references/scoring-standard-v2.md`。

报告模型的职责：

- 仅在指定维度内识别已知事实；
- 按已发布 `criterionId` 归类证据方向；
- 标记来源与是否为直接证据；
- 生成克制的核心判断与行动文字；
- 不输出最终 `score / confidence / dataCompleteness`。

确定性评分引擎的职责：

- 校验 criterionId；
- 依据基础分、权重、方向与完整度计算 `0~10` 分；
- 依据关键证据覆盖、加权完整度和直接证据数量计算置信度；
- 在资料不足时执行向 `5.0` 中性基准收缩；
- 为每条 evidence 记录评分规则版本。

## 6. 医学边界

- AMH/AFC 主要反映卵巢储备和促排反应，不直接衡量卵子质量或自然受孕概率；
- 女性年龄属于时间窗口与卵母细胞背景，不是疾病，也不单独代表最终结局；
- 单一精液参数不是男性不育诊断；WHO 参考下限用于实验室解释而非个人诊断分界；
- DFI、免疫、凝血、NK、封闭抗体等在无临床指征时不是人人必查，未检测不扣分；
- TSH 采用实验室参考区间和临床情境解释；备孕阶段 2.5–4.0 mIU/L 不自动扣分；
- 外周血炎症指标不得直接替代生殖道炎症证据；
- 不把具体干预写成确定性获益，不承诺提高个人成功率、妊娠率或活产率；
- PGT、促排、移植、药物、补充剂和手术仅可作为与专科医生讨论的适用性、潜在获益、风险与局限问题。

## 7. 生成策略

允许使用受限报告模型做证据归类和汇总，但必须满足：

- 输入受限于当前 assessment state、病例 JSON 和证据账本；
- 不补造检查结果；
- 不形成自治 Agent loop；
- 不绕过 Planner / Policy / Evidence / Harness 去调用外部能力；
- 模型输出先经过评分规则校验、确定性计算与内容治理，再进入报告状态。

个人报告一次生成对应十维内容；夫妻报告分别生成女方十维、男方十维，再生成联合摘要。每次均看到同一份完整病例状态。

报告正文、图表、HTML 和 PDF 不允许分别让 LLM 独立生成多套内容。

## 8. 行内 HTML、目录与图表

行内 HTML 是主要可读交付：

- 在聊天中由宿主 artifact renderer 通过 sandboxed iframe 或等价安全容器展示；
- UChat 通用层只提供 artifact 插槽，不感知生育报告业务；
- 章节、维度字段和结论必须与 assessment state 一致；
- 雷达图与评分条由最终数值状态在 renderer 中静态生成；
- 禁止依赖打印阶段临时执行脚本补图；
- HTML 生成成功即应保留并可交付，不应因 PDF 环境失败而丢弃。

目录规则：

- 封面后生成一页自动目录；
- 目录包含主要章节和当前范围内的女性 / 男性维度；
- 行内 HTML 可点击跳转；
- PDF 页码由 CSS `target-counter()` 自动计算，不硬编码；
- 章节标题用于生成 PDF 书签时，不应暴露内部维度 ID。

## 9. 分页层级

- 封面独立页面；
- 目录独立页面；
- 女性综合画像、男性综合画像等大章可以另起页；
- 单个维度不强制另起页，避免大量空白；
- 维度标题、分数、置信度、完整度、进度条、核心判断标题与首段构成不可拆的章节开场组；
- 当前页放不下开场组时，整组移动到下一页；
- 维度之间使用浅色细分隔，不使用与一级大章同等级的粗横线；
- 长正文允许自然跨页，列表保留孤行寡行保护。

## 10. PDF

PDF 必须直接从同一份最终 HTML 生成：

```text
final HTML with inline SVG and semantic anchors
→ Vivliostyle CLI
→ system Chrome / Edge rendering runtime
→ PDF artifact
```

Vivliostyle 负责：

- `@page` 页面模板；
- 封面无页眉页脚；
- 正文页眉、页脚和页码；
- 自动目录页码；
- 章节开场分页保护；
- 长内容跨页。

禁止让 LLM 再独立写一次 PDF 内容，也禁止在打印阶段重新计算评分或动态插图。

如果本机 PDF 转换环境不可用：

- 行内 HTML 仍必须正常交付；
- 明确标记 PDF 暂不可用；
- 不回退旧 Playwright PDF；
- 不得把整个报告任务错误标记为“没有结果”。

## 11. 完成语义

以下状态都不能单独视为完整用户任务完成：

```text
只完成访谈
只得到 assessment JSON
只得到 flowCompleted=true
只产生 next.intent=generate_report
只计算出维度分数
```

完整交付至少要求：

```text
assessment state ready
+ 所选全部维度具有数值分与置信度
+ report generated
+ inline HTML available to user
```

PDF 是可用时的附加交付；PDF 失败允许降级，但必须留下明确失败信息。

## 12. 增量更新

当用户后来提供新的事实、检查结果或治疗信息：

```text
新信息
→ 更新 assessment state
→ 重新归类受影响证据
→ 确定性重算受影响维度 / summary
→ 重新应用内容治理
→ 从新 state 重新渲染图表与报告
```

不要直接在旧报告文字或 SVG 上手工改结论，否则结构化状态、评分和报告会失去一致性。
