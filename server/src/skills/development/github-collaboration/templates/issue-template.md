# Issue Template

```markdown
# <清晰、可搜索的标题>

## 背景
为什么需要处理这件事。

## 当前行为
现在发生了什么；附可验证事实。

## 期望行为
完成后应该是什么状态。

## 范围
- 包含：
- 不包含：

## 验收标准
- [ ] 可观察结果 1
- [ ] 可观察结果 2
- [ ] 失败/恢复路径得到验证

## 风险与依赖
- 风险：
- 依赖：
- 权限或环境要求：

## 验证方式
说明如何证明 Issue 已完成。
```

使用规则：

- 不要保留没有内容的空章节；
- 验收标准必须可验证；
- 技术实现不是唯一方案时，优先描述结果合同；
- labels、assignees 和 milestone 必须有依据；
- 创建前先搜索重复项。
