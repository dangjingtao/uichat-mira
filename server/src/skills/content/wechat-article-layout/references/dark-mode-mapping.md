# 微信深色模式颜色映射实测表（2026-07 真机）

探测方法：23 色色卡探针（9 背景 + 10 文字 + 4 边框）贴入草稿，公众号后台【预览】发真机，系统浅色/深色模式各截图，PIL 逐像素取样。工作目录存档：dark-mode-probe.html、probe-light-1/2.jpg、probe-dark-1/2.jpg。

## 总规则

- **浅色模式：零映射，所写即所得**（所有色值原样渲染，误差仅为 JPEG 噪声）。
- **深色模式：微信客户端强制 remap**，背景、文字、边框三套规则不同。
- 图片不参与映射，两模式均保真。

## 背景色 background-color（深色模式）

| 原色 | 深色渲染 | 结论 |
|---|---|---|
| #0c0c0c | #383838 | 压成统一中灰 |
| #111111 | #383838 | 同上，灰度层次全灭 |
| #1a1a1a | #383838 | 同上 |
| #2a2a2a | #383838 | 同上 |
| #142218（暗绿） | #314635 | **色相保留**，但亮度压平 |
| #1e3326（暗绿） | #314637 | 两个不同的绿被压成**同一个**绿灰 |
| #666666 | #666666 | 中灰不变（雷区，见下） |
| #f7f7f7 | #212121 | 亮色反转为深灰 |
| #ffffff | #191919 | 纯白反转为更深灰 |

要点：暗灰（≤#2a2a2a）全部压成同一个 #383838；带色相的暗色保留色相但亮度同样压平（深浅不同的同色系合并）；亮色反转。

## 文字色 color（深色模式）

| 原色 | 深色渲染 | 结论 |
|---|---|---|
| #f0f0f0 | ≈#f2f2f2 | 不变 |
| #c8c8c8 | #c8c8c8 | 不变 |
| #888888 | #898989 | 不变 |
| #666666 | #828282 | 微提亮 |
| #3f3f3f | #a8a7a7 | 大幅提亮（对比度救援） |
| #1a1a1a | #cdcdcd | 近黑翻转为近白！ |
| #7fb285 / #8fbc8f | ≈原值 | 绿色幸存 |
| #4a7c59 | ≈#809a88 | 深绿提亮，可读性更好 |
| #d08080 | ≈原值 | 红色幸存 |

经验公式：渲染 ≈ max(原色, 0.85 × 反相)——暗文字被"对比度救援"式提亮，亮文字不变，彩色保色相。深色模式下文字永远可读，但文字色的深浅层次同样被压平。

## 边框色 border-color（深色模式）

| 原色 | 深色渲染 | 结论 |
|---|---|---|
| #4a7c59 | ≈#57785d | 不变 |
| #666666 | #666666 | 不变 |
| #2a2a2a | #989898 | 暗边框被提亮（救援） |
| #a05555 | ≈#915a5d | 不变 |

边框同文字规则：暗的被提亮，彩色保色相。**深色模式下边框始终可见，是可靠的层次手段。**

## 雷区

- **中灰背景（#666666 量级）不可预测**：背景本身不变，但其上的亮文字（#c8c8c8）会被压暗成 #2b2b30（上下文相关映射）。不要把文字放在中灰底上。
- "#xxxxxx" 形式的文本会被微信渲染成话题链接蓝紫色（#656a83 量级），两模式皆然——色卡类内容注意。

## 设计规则（v6 定稿）

1. 层次**只能**靠：色相差异（绿/红 vs 灰，深色模式下幸存）、左边框（始终可见）、留白、字重。**禁止**靠暗灰度差（0c/11/1a/2a 夜间全合并）。
2. 同色系深浅双档（如 #142218 vs #1e3326）夜间合并为一档——预设里每色相只设一档。
3. 文字色放心用，微信夜间会自动保可读性；但别指望文字深浅表达主次（#666 以下全被提亮拉平）。
4. terminal-dark 现有配色实测**双模式安全**，无需改色；夜间的代价只是灰度层次压平（绿/红引用块仍可区分，灰引用块靠 #666 左边框区分）。
5. minimal-light 等浅底预设夜间会被整体反转（白底→#191919、黑字→近白），同样可读——选风格是审美问题，不是可用性问题。
